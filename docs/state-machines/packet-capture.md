# 抓包环境配置

`setup_packet_capture` 在同一设备操作锁中执行，证书安装与 Reqable 配置始终固定到同一台设备。

| 阶段 | 条件与后续行为 |
| --- | --- |
| 检查设备和客户端 | 固定在线设备，读取当前用户已安装的 FGO 候选包并确定客户端；只有一个时自动选中，多个时必须由用户选择。支持直接选择渠道服。没有候选或之前选中的客户端已卸载时明确报错并结束配置。随后检查 Reqable 是否安装及 Android 版本。 |
| 准备 root 权限 | 先检查 ADB shell 和已有 `su` 提权方式。已可取得 UID 0 时直接继续；否则仅向绑定设备发送 `adb root`，等待同一设备重连，再次验证 UID 0。命令返回成功不代表提权成功；命令回复丢失时也以重连后的实际权限为准。失败时保留 ADB 返回的原因并结束配置。检查、尝试、等待和验证结果均同步到环境配置进度。 |
| 打开 Reqable | root 验证成功后打开主 Activity，继续证书初始化与安装。 |
| 检查首次启动界面 | 读取有大小上限的 UIAutomator XML，只匹配 `com.reqable.android` 的协议标题及确认按钮。支持英文 `License Agreement` / `Accept` 和中文 `用户许可协议` / `同意`。Flutter 的文字从 `content-desc` 或 `text` 读取；禁用且不可点击的确认按钮仍视为待确认。 |
| 等待用户确认 | 将提示写入普通操作日志；最多等待 120 秒，由用户在设备上阅读并确认协议。左下角实时显示“当前为服务条款页面，请滑动到底部并点击底部按钮接受条款”。协议阅读和确认由用户在设备上完成。 |
| 选择工作模式 | 匹配 `Work Modes` / `工作模式` 标题及可点击的 `Standalone Mode` / `独立模式` 选项，使用节点 bounds 中心加小幅偏移点击一次。重新读取页面后，点击右上角“下一步”：兼容已提供中英文 XML 中无标签的控件，限于标题所在行、屏幕右侧且唯一的可用节点。两次点击均只尝试一次，持续检测页面是否离开；按钮不可识别或点击失败时等待用户手动完成，进入后续页面后读取 CA。独立出现该页时最多等待 30 秒。左下角及操作日志提示“检测到 Reqable 工作模式选择页，正在自动处理，如无响应请手动选择独立模式并进入下一步”。 |
| 等待初始化 | 确认 Reqable 仍在前台且协议页、工作模式页均已消失后等待 CA 文件出现；切换到桌面或其他应用时继续等待确认。没有首次启动页面时保留短初始化等待；界面暂不可读时重试，若从未识别到待确认的协议或工作模式页，允许使用已存在且验证有效的 CA 继续。已识别的协议页必须等待用户确认；证书缺失或等待超时明确报错。 |
| 安装证书 | 解析并验证 CA 后执行既有安装脚本并检查结果。 |
| 配置 Reqable | 根据应用当前服务器默认配置为仅抓所选国服或日服 FGO，关闭自动抓包，保留备份、回读验证和失败回滚。缺失的受管字段可补齐，已存在字段类型错误仍拒绝写入；回读核对 Mash 修改的字段，其余配置字段保留现有值。配置完成时抓包仍关闭。 |
| 关闭系统画中画 | 配置文件写入后、重新打开 Reqable 前，通过 `cmd appops` 将用户 0 的 `com.reqable.android` 的 `PICTURE_IN_PICTURE` 设为 `ignore`，并回读确认。已关闭时复用当前权限状态；存在 UID 允许覆盖、命令失败或回读不一致时保留提醒，继续完成配置。只修改这一应用的一项权限，成功关闭的系统权限持续保持关闭，用户可在 Android 设置中重新开启。 |
| 开始抓包 | 检查 VPN 模式和所选客户端的覆盖情况，尽力关闭并回读系统画中画权限，然后打开 Reqable 和发送抓包请求。额外选中其他应用、开启自动抓包或主机模式时允许启动。画中画权限无法确认时提醒并继续。Reqable 返回 active 后等待 VPN 状态更新并最多读取四次；范围包含其他应用或无法解析时提醒并继续。只有确认属于 Reqable 的 VPN 明确未覆盖目标游戏时才拒绝启动；游戏或 Reqable UID 读取失败时提醒并继续。 |
| 打开游戏 | 抓包确认启动并完成 VPN 范围检查后，在绑定设备上按 MAIN / LAUNCHER Intent 查询所选客户端的启动 Activity，再通过显式组件启动，支持国服官服、渠道服和日服。自动打开失败时，下方等待消息显示“等待数据中，自动启动游戏失败，请重新进入游戏……”，继续等待游戏登录响应；启动错误详情写入调试日志。此步骤支持取消。 |
| 等待数据 | 抓包确认启动后显示“等待数据中，请重新进入游戏……”，持续查找本次所选服务器的登录原始响应。临时连接及 ADB 故障保留 waiting 状态，按 2、4、8 秒（上限）退避，恢复后继续；重试期限由 Rust 管理并返回 retryAfterMs。认证失效、控制接口关闭或协议无法解释时进入 error，仍保留停止入口。单次登录 HTTP 失败或单条记录不可用时，跳过当前响应并继续等待。 |
| 请求停止 | 配置、启动及抓包运行期间，主要按钮均为可点击的“停止”。停止请求先通知当前任务取消，继续持有设备锁直到当前原子设备命令及必要回滚结束，再把设备锁交给停止任务；期间由当前任务独占设备锁，其他自动化保持原状态。 |
| 停止收尾 | 若中断配置或启动，固定到原任务绑定的设备，关闭 Reqable 并检查进程退出，以取消待确认的 VPN 启动。已在等待响应时按既有 API 关闭并验证抓包状态。停止期间显示“正在停止，等待当前设备操作结束…”，禁止重复点击；成功记录“环境配置已停止”或“抓包已停止”，失败写入警告日志并保留原设备供重试。 |

停止后保留已完成的证书安装；若配置写入后被取消，会先回滚配置文件，回滚失败保留备份并记录警告。协议及轮询等待可立即唤醒，正在执行的 ADB 原子命令会在当前命令结束后停止后续步骤。界面使用请求代次忽略被停止任务的迟到进度、成功、错误及结束回调，后台停止确认后才允许新任务开始。

配置、启动、等待响应及停止期间禁止离开抓包页面：禁用返回、设置和调试入口，并忽略菜单的资源管理请求。启动成功后，在后台页面状态刷新完成前继续锁定导航；轮询读取失败仍保留锁定和停止入口。只有停止确认成功或抓包完成后恢复导航；停止失败且仍绑定设备时继续锁定，允许重试停止。

辅助检查及旧记录提醒通过后端 warnings 字段持续返回，页面在独立提醒区域展示，与普通进度和成功消息并列。界面 dump 使用独立临时文件并在读取后清理。完成初始化后安装证书并写入 Reqable 配置。配置期间通过 `packet-capture-setup-progress` 字符串事件同步左下角状态，操作日志仍保留完整步骤。单元测试使用中英文协议页和工作模式页真实层级结构的精简 fixture，覆盖等待协议确认、选择独立模式、点击下一步及离开页面后读取 CA。

系统画中画权限依据 Android 的 [ActivityRecord 权限检查](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android13-release/services/core/java/com/android/server/wm/ActivityRecord.java)及 [AppOps 命令实现](https://android.googlesource.com/platform/frameworks/base/+/b9c4862b8605b653153be29ed902142539f4ffe2/services/core/java/com/android/server/appop/AppOpsService.java)。权限回读测试覆盖命令未生效、UID 覆盖和连接失败。

控制接口分别限制连接和请求时间：建立连接最多等待 2 秒，完整请求及响应读取最多等待 30 秒，以容纳记录筛选等较慢操作。连接失败、连接超时和接口响应超时分别报告。

## 版本与 API key 授权

最低支持版本仍为 3.3.5；版本解析支持额外数字段、`v` 前缀和版本后缀，最低版本及 3.3.9 起的 API key 判断共用解析器。版本未知时按已知且类型兼容的字段继续配置；启动时通过无副作用的 status 接口探测是否可用及是否需要认证。

已有有效 key 仍按设备复用。需要授权时，Rust 创建绑定设备、请求 UUID 和取消令牌的临时授权请求，界面通过 get_packet_capture_authorization 读取请求 ID、设备及授权进度。自动剪贴板不可用、前台信息不可读或用户主动输入时，可通过 submit_packet_capture_api_key 提交 key；验证、保存和启动仍在持有设备锁的原任务中完成。验证中禁止重复提交，认证失败可重新输入，临时连接失败先有限重试；请求结束、取消或超时后清理待提交 key，拒绝旧 UUID 的迟到提交。

抓包状态消息提供“手动输入”入口，点击后打开授权弹窗，展示当前授权进度和密码输入框。关闭弹窗后继续等待授权。前端保留输入草稿，在提交成功、关闭弹窗、请求变化或结束后清除；key 由后端验证并按设备保存。授权期间仍可使用页面上的停止按钮。授权总等待沿用 120 秒，状态读取失败时重试，原启动任务继续执行。

## 服务器与登录响应

环境配置、单独安装证书、配置 Reqable 和启动抓包均读取应用现有服务器设置。每次操作固定服务器、设备和完整客户端包名；响应轮询、基线记录及完成提示固定使用启动时的服务器。切换服务器后需重新点击“环境配置”，更换客户端也需重新配置；启动时若应用筛选明确未覆盖当前客户端则报错；筛选覆盖其他应用或范围无法确认时提醒并继续。

| 服务器 | Reqable 应用筛选 | 登录响应匹配 |
| --- | --- | --- |
| 国服 | 用户选择的完整包名：官服 `com.bilibili.fatego` 或渠道服包名 | 既有 Bilibili FGO 域名及 `rongame_beta/rgfate/<版本>/ac.php`，查询参数仅有一个 `_key=toplogin`。 |
| 日服 | `com.aniplex.fategrandorder` | `https://game.fate-go.jp/login/top`，精确校验域名和路径。 |

抓包页顶部使用与 PARTY 一致的下划线下拉入口（CLIENT），直接展开设备上的客户端候选列表；选中后收起并显示完整包名。选择由 Rust 按服务器和设备保存到应用数据目录的 `packet-capture/clients.json`，单一候选的自动选择也会保存；进入页面后自动读取客户端列表并恢复显示。恢复时核对设备上的安装列表，已卸载的客户端保持待选择状态。读写记录失败时保留本次运行中的选择并记录提醒。列表将客户端类型及完整包名显示在同一行，复用队伍选择列表的行高；刷新放在下拉入口旁的三点功能菜单中。未选择时提示“请在顶部选择需要抓包的客户端，再进行环境配置”。候选由 Rust 读取 `pm list packages --user 0` 后识别：日服匹配官方完整包名，国服按现有游戏识别惯例匹配 `fgo` / `fatego` / `fategrandorder`，排除已知日、美、台、韩服包名前缀。包名只允许字母、数字、下划线和点，并再次核对设备上实际安装的列表。客户端候选依据包名匹配结果生成。

环境配置及开始前会再次确认选择，后续证书安装、Reqable 配置、应用 UID 查询和 VPN 范围检查始终使用同一个完整包名。国服官服和渠道服使用同一组登录响应匹配规则，包含 `-uo-fate.bilibiligame.net` 渠道域名。

两服均校验 HTTPS 默认端口及 URL 用户信息为空。Reqable 先按各服路由关键字筛选，再由后端严格检查 URL；国服显示地址仅保留路由参数，日服移除全部查询参数，两者均移除片段，避免显示账户参数。启动前仅将本服已有记录 UID 加入基线，记录列表响应按 128 KiB 字节上限读取。每 16 条更新识别进度，每条前后检查取消，并保留 Reqable 历史。单条旧记录无法识别时，将其数字 ID 加入本次忽略集合并提醒，即使后续 ID 复用也保守忽略；已识别 UID 的记录仍允许同一数字 ID 对应的新 UID 被捕获。整个记录列表无法取得时报告错误，取得基线后再发送开始请求。本次结果仅采用当前服务器的新完成响应。取得完整响应后沿用自动停止、持久化、原始内容复制/导出及账户物品预览。

Android 14+ 证书安装脚本将所选服务器的游戏包名用于运行中进程的命名空间挂载与回读验证，未启动游戏仍由 Zygote 继承证书。日服包名见 [Google Play 官方页面](https://play.google.com/store/apps/details?id=com.aniplex.fategrandorder)，登录路径参考 [Chaldea 抓包插件源码](https://github.com/chaldea-center/mitm-fgo/blob/main/fgoaddon.py)。自动测试覆盖两服配置隔离、切服配置不符、日服进程证书安装、登录 URL 边界、旧记录/异服记录排除、原始 JSON 与物品预览、自动停止成功和失败。

## 抓包历史

应用数据目录中的 `packet-capture/index.json` 只保存版本、记录 ID、获取时间及设备序列号，完整原始响应和物品预览各自保存在 `<UUID>.json`。页面接口返回抓包状态、历史索引和默认记录 ID；界面先显示列表及选中状态，再单独异步读取对应记录。文件通过缓冲读取，在历史索引锁外完成解析。旧版没有索引的历史只在迁移时完整扫描一次，成功后原子保存索引，原始记录不变；索引损坏时明确报错并保留现有数据。

首次进入页面时，历史列表、响应及账户物品显示 Radix Skeleton；索引返回后列表即可操作，完整数据仍在加载时保留右侧 Skeleton。点击其他记录立即切换高亮和时间，随后才请求完整记录。快速连续切换时忽略旧请求的结果和错误；读取失败停止占位并提示，可再次点击当前记录重试。读取期间禁用复制但允许切换历史和返回；复制明确指定当前已加载记录的 ID。前端保留当前展示的一条记录，历史响应缓存由 Rust 管理。

响应栏的复制和导出均为无背景按钮，使用 Radix 图标。导出明确指定当前已加载记录的 ID，通过系统保存对话框选择位置，默认文件名为 `mash-capture-<获取时间戳>.txt`；原子写入与复制内容逐字节一致的完整原始响应。无记录或加载期间禁用导出，进行中禁止重复请求，取消保存时退出导出流程。

Rust 中的完整响应使用 LRU 缓存，最多 3 条且保留的记录内存合计不超过 32 MiB，任一条件超限时淘汰最久未使用的记录。计入字符串、物品数组及名称的分配容量；单条超过预算时直接提供查看和复制。共享引用避免为缓存命中再次复制完整响应。此预算用于管理历史缓存内存。

新记录先原子保存完整文件，再原子更新索引；删除先提交索引及待删除标记，再删除完整文件并清理标记。清理中断或失败时保留待删除项，后续操作或重启时继续清理待删除项。删除同时移除相应缓存；解析完成后确认记录仍存在，再加入缓存。切换记录复用页面索引，删除使用返回的新索引，复制成功后继续使用现有索引；正在抓包时正常按每轮结束后间隔 1 秒查询，临时故障按后端返回的退避间隔查询，普通索引刷新保留用户选择，新抓到响应时自动切换至最新记录。
