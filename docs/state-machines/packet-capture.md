# 抓包环境配置

`setup_packet_capture` 在同一设备操作锁中执行，证书安装与 Reqable 配置始终固定到同一台设备。

| 阶段 | 条件与后续行为 |
| --- | --- |
| 打开 Reqable | 检查设备、应用、Android 版本和 root；打开主 Activity。 |
| 检查首次启动界面 | 读取有大小上限的 UIAutomator XML，只匹配 `com.reqable.android` 的协议标题及确认按钮。支持英文 `License Agreement` / `Accept` 和中文 `用户许可协议` / `同意`。Flutter 的文字从 `content-desc` 或 `text` 读取；禁用且不可点击的确认按钮仍视为待确认。 |
| 等待用户确认 | 将提示写入普通操作日志；最多等待 120 秒，由用户在设备上阅读并确认协议。左下角实时显示“当前为服务条款页面，请滑动到底部并点击底部按钮接受条款”。此阶段不点击、不滚动、不修改协议接受标记。 |
| 选择工作模式 | 匹配 `Work Modes` / `工作模式` 标题及可点击的 `Standalone Mode` / `独立模式` 选项，使用节点 bounds 中心加小幅偏移点击一次。重新读取页面后，点击右上角“下一步”：兼容已提供中英文 XML 中无标签的控件，限于标题所在行、屏幕右侧且唯一的可用节点。两次点击均只尝试一次，持续检测页面是否离开；按钮不可识别或点击失败时保留手动完成的等待，不读取 CA。独立出现该页时最多等待 30 秒。左下角及操作日志提示“检测到 Reqable 工作模式选择页，正在自动处理，如无响应请手动选择独立模式并进入下一步”。 |
| 等待初始化 | 确认 Reqable 仍在前台且协议页、工作模式页均已消失后等待 CA 文件出现；切换到桌面或其他应用不视为确认。没有首次启动页面时保留短初始化等待；界面不可读、证书缺失或等待超时均明确报错。 |
| 安装证书 | 解析并验证 CA 后执行既有安装脚本并检查结果。 |
| 配置 Reqable | 按既有流程配置为仅抓国服 FGO，保留备份、回读验证和失败回滚。`pipMode` 未验证有效，不再作为配置目标或启动条件；已有字段按其他未知设置保留。配置完成时抓包仍关闭。 |
| 关闭系统画中画 | 配置文件写入后、重新打开 Reqable 前，通过 `cmd appops` 将用户 0 的 `com.reqable.android` 的 `PICTURE_IN_PICTURE` 设为 `ignore`，并回读确认。已关闭时不重复写入；存在 UID 允许覆盖、命令失败或回读不一致时明确报错，环境配置不报告成功。只修改这一应用的一项权限，已关闭的系统权限不会随配置文件回滚或停止抓包恢复；用户可在 Android 设置中重新开启。 |
| 开始抓包 | 检查仅抓国服配置后，再次关闭并回读系统画中画权限，然后才打开 Reqable 和发送抓包请求。旧版已配置的设备可直接点击开始，无需为了关闭画中画重跑证书安装。权限无法确认时不发送抓包请求。 |
| 等待数据 | 抓包确认启动后显示“等待数据中，请重新进入游戏……”，持续查找国服 toplogin 原始响应。 |
| 请求停止 | 配置、启动及抓包运行期间，主要按钮均为可点击的“停止”。停止请求先通知当前任务取消，继续持有设备锁直到当前原子设备命令及必要回滚结束，再把设备锁交给停止任务；期间禁止新设备任务插入，不中断其他自动化。 |
| 停止收尾 | 若中断配置或启动，固定到原任务绑定的设备，关闭 Reqable 并检查进程退出，以取消待确认的 VPN 启动。已在等待响应时按既有 API 关闭并验证抓包状态。停止期间显示“正在停止，等待当前设备操作结束…”，禁止重复点击；成功记录“环境配置已停止”或“抓包已停止”，失败写入警告日志并保留原设备供重试。 |

停止不撤销已完成的证书安装；若配置写入后被取消，会先回滚配置文件，回滚失败保留备份并记录警告。协议及轮询等待可立即唤醒，正在执行的 ADB 原子命令会在当前命令结束后停止后续步骤。界面使用请求代次忽略被停止任务的迟到进度、成功、错误及结束回调，后台停止确认后才允许新任务开始。

配置、启动、等待响应及停止期间禁止离开抓包页面：禁用返回、设置和调试入口，并忽略菜单的资源管理请求。启动成功后，在后台页面状态刷新完成前继续锁定导航；轮询读取失败仍保留锁定和停止入口。只有停止确认成功或抓包完成后恢复导航；停止失败且仍绑定设备时继续锁定，允许重试停止。

界面 dump 使用独立临时文件并清理，不将完整 XML 写入日志。尚未完成初始化时不会安装证书或写入 Reqable 配置。配置期间通过 `packet-capture-setup-progress` 字符串事件同步左下角状态，操作日志仍保留完整步骤。单元测试使用中英文协议页和工作模式页真实层级结构的精简 fixture，覆盖等待协议确认、选择独立模式、点击下一步及离开页面后读取 CA；真机验证仍需设备环境。

系统画中画权限依据 Android 的 [ActivityRecord 权限检查](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android13-release/services/core/java/com/android/server/wm/ActivityRecord.java)及 [AppOps 命令实现](https://android.googlesource.com/platform/frameworks/base/+/b9c4862b8605b653153be29ed902142539f4ffe2/services/core/java/com/android/server/appop/AppOpsService.java)。权限回读测试覆盖命令未生效、UID 覆盖和连接失败；设备上的实际窗口效果仍需验证。

## 抓包历史

应用数据目录中的 `packet-capture/index.json` 只保存版本、记录 ID、获取时间及设备序列号，完整原始响应和物品预览各自保存在 `<UUID>.json`。页面接口只返回抓包状态、历史索引和默认记录 ID，不附带完整响应；界面先显示列表及选中状态，再单独异步读取对应记录。文件通过缓冲读取，解析不占用历史索引锁。旧版没有索引的历史只在迁移时完整扫描一次，成功后原子保存索引，原始记录不变；索引损坏时明确报错，不重新扫描或覆盖数据。

首次进入页面时，历史列表、响应及账户物品显示 Radix Skeleton；索引返回后列表即可操作，完整数据仍在加载时保留右侧 Skeleton。点击其他记录立即切换高亮和时间，随后才请求完整记录。快速连续切换时忽略旧请求的结果和错误；读取失败停止占位并提示，可再次点击当前记录重试。读取期间禁用复制但允许切换历史和返回；复制明确指定当前已加载记录的 ID。前端只保留当前展示的一条记录，不另外缓存历史响应。

响应栏的复制和导出均为无背景按钮，使用 Radix 图标。导出明确指定当前已加载记录的 ID，通过系统保存对话框选择位置，默认文件名为 `mash-capture-<获取时间戳>.txt`；原子写入与复制内容一致的完整原始响应，不解码、不包裹 JSON、不额外添加换行。无记录或加载期间禁用导出，进行中禁止重复请求，取消保存不写入文件，也不显示成功。

Rust 中的完整响应使用 LRU 缓存，最多 3 条且保留的记录内存合计不超过 32 MiB，任一条件超限时淘汰最久未使用的记录。计入字符串、物品数组及名称的分配容量；单条超过预算时允许查看、复制，但不加入缓存。共享引用避免为缓存命中再次复制完整响应。此预算只约束历史缓存，不包含 IPC 序列化、当前抓包状态及前端展示所需内存。

新记录先原子保存完整文件，再原子更新索引；删除先提交索引及待删除标记，再删除完整文件并清理标记。清理中断或失败时保留待删除项，后续操作或重启重试，不重新导入已删除记录。删除同时移除相应缓存；解析完成时若记录已删除，不再加入缓存。切换记录不重复请求页面索引，删除和复制成功后也不立即重复请求；正在抓包时仍按每轮结束后间隔 1 秒查询，普通索引刷新保留用户选择，新抓到响应时自动切换至最新记录。
