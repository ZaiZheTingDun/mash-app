# 设备触控

自动化通过 `src-tauri/src/touch/TouchBackend` 使用点击、滑动和滑动后停留。战斗、从者强化、礼装强化和友情点召唤共用工厂；坐标抖动仍由外层 `HumanizedTouch` 统一应用。

“游戏 → 基础设置 → 触控方式”可选择 scrcpy 或 ADB Input（旧版），选择由后端保存在 `touch_control_settings.json`，从下次任务启动生效；正在运行的手势不切换后端。选择 ADB Input 时仅使用原有 ADB 输入，并关闭新视频会话的 scrcpy 控制通道。切换偏好后，调试入口也会重新建立视频会话，避免复用旧控制方式。

默认选择 scrcpy，优先使用当前视频会话的控制通道；旧 sidecar 未返回控制能力、会话设备不匹配或初始化不支持控制时，选择 ADB Input。启动 scrcpy 控制失败时，sidecar 尝试重启为纯视频会话，保留 ADB 输入路径。Android 10 之前的非主显示屏不启用 scrcpy 控制。

## 模块边界

- `touch/scrcpy.rs`：Rust 生成完整的单指手势和时间表，将设备像素换算为视频像素。移动和终点停留阶段都按约 16ms 采样，合计受 604 个事件的协议上限约束；带停留拖动先按住起点 80ms，再等速移动到终点；普通滑动保持原有线性时间表。点击按住 40ms，长按沿用调用方的停留时长。单次手势最多 60 秒。
- `screen/input.rs`：绑定视频会话的输入句柄，通过 `scrcpy_touch` 发送 `streamId`、视频尺寸和事件数组。与识别请求共享串行 JSON-line 传输及递增请求 ID，避免响应串线；runner 不依赖 scrcpy 协议。
- `mash_cv/stream.py`：管理同一 scrcpy 2.7 服务的两个 socket。关闭音频时先连接视频并读取 dummy，再连接控制，最后读取视频元数据。控制随视频停止而释放，不额外启动设备端服务。
- `mash_cv/scrcpy_control.py`：编码 2.7 的 32 字节触摸消息，按单调时钟执行 Rust 提供的时间表；调度迟到或发送阻塞时将后续时间向后平移，保留事件间隔，不突发补发过期事件，也不压缩终点停留。先校验完整 DOWN → MOVE → UP 序列，再发送；中途失败尝试释放触点并禁用该控制句柄，等待重新启动视频会话。

事件字段为 `action`（0 DOWN、2 MOVE、1 UP）、`x`、`y`、`atMs`（从手势开始累计的毫秒数）。所有事件使用同一个 finger pointer ID。滑动停留期间持续发送终点 MOVE，再 UP，向速度估算提供连续静止采样。助战仍在终点按住 250ms，松手后的画面等待按后端投递能力选择：scrcpy 的连续事件流使用 150ms，ADB Input 保留原来的 450ms。`TouchBackend::timing()` 提供投递类型，助战流程负责选择等待时长，坐标抖动包装层透传该能力；不按后端名称判断。时间表描述发送时间，无法保证设备端调度精确到该毫秒。

输入必须匹配当前会话标识和最新视频帧尺寸，解码线程必须仍在运行。会话重启、画面旋转导致尺寸变化或控制发送失败时返回带原请求 ID 的错误响应，识别进程和视频会话继续保留；不在同一手势中自动切换 ADB 重发，避免重复点击。scrcpy 输入是异步注入，成功响应仅确认消息已发送，不保证 Android 已接收或游戏已响应；动作结果仍通过原有画面识别确认。

## 对比验证

通过设置选择触控方式后重新启动任务即可对比；调试日志显示 `[touch] backend selected: scrcpy`。使用 `MASH_TOUCH_BACKEND=adb pnpm tauri dev` 可在本次应用进程内强制选择 ADB Input；不写入持久化设置。选择 ADB 时不启用 scrcpy 控制通道。

离线测试覆盖协议字节、视频坐标缩放、起点按住、等速移动和终点停留时间表、握手顺序、会话和尺寸拒绝、断线触点释放及初始化回退。设备验证应比较两种后端的点击响应、列表滑动耗时与落点、长按、停止重启和 MuMu 非主显示屏；离线测试不能代替设备权限、输入注入和游戏响应验证。
